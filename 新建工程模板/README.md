# 新建工程模板（已验证，复制即用）

> 本文件夹是一个**已经验证过、保证能编译成功**的完整 C51 工程骨架。
> 不要再走 EIDE「新建项目」流程 —— 它生成的模板缺东西（见《开发环境重建指南》4.5 根因分析），
> 每次新建都要手工补，很容易漏。直接复制本文件夹最快、最稳。

## 目录结构（每个文件的作用）

| 文件 | 作用 |
|---|---|
| `.eide/eide.yml` | 工程配置：已包含 `inc` 包含路径 + Keil Atmel 绝对路径 + Keil_C51 工具链 + STARTUP.A51 注册 |
| `.clangd` | clangd 配置（完整注释版）：宏翻译 + `-Iinc`/`-I../inc` 互补路径 + 编译数据库 + 抑制清单，**零工程专属路径** |

## `.clangd` 需要改吗？（不需要）

`.clangd` 里**没有任何工程专属路径**——工程内头文件靠 `-Iinc`（有编译数据库时按工程根解析）+
`-I../inc`（没编译过时按文件所在目录解析）两条互补相对路径，**工程复制到哪、叫什么名字都不用改**。

只有两种情况才动它：
1. **换机器 / 换盘**：改 Keil 那两行 `-ID:/Keil5/...` 为实际路径
2. **目标名不是 Target 1 的工程**（如 SDCC 模板新建的工程是 Debug）：改 `CompilationDatabase: ./build/Target 1` 一行

## 使用方法（三步）

1. **复制**：把整个 `新建工程模板` 文件夹复制到你的工程目录（比如 `D:\Users\Documents\C51\`），
   然后把文件夹改名为你的工程名（如 `myproj`）。改名后 eide.yml 里的 `name` 字段不用改也能编译；
   想改的话在 EIDE 里改（见步骤 3 的说明）。

2. **打开**：VSCode → 文件 → 打开文件夹 → 选中刚复制改名后的文件夹。

3. **编译**：按 `F7`。看到 `[ DONE ] build successfully !` 即成功。
   生成的烧录文件在 `build\Target 1\myproj.hex`。
   （可选：左侧 EIDE 面板 → 项目设置 → 项目名改成你的名字，改完自动写回 eide.yml）

## 为什么这个模板保证成功（原理）

1. **包含路径 `inc` 已写入 incList** —— EIDE 新建的模板只有 Atmel 路径，
   `#include "uart.h"`（头文件在 inc/）会报 `can't open file 'uart.h'`。这是新工程失败的**头号根因**。
2. **Atmel 路径用绝对路径** `D:/Keil5/C51/C51/INC/Atmel` —— 不依赖工程所在深度，
   放几层深的文件夹都不会错（相对路径 `../../../../` 少写一层就找不到 REGX52.H）。
   Keil 标准 INC 目录（REGX52.H/stdio.h）由 EIDE 自动附加，不用管。
3. **`.clangd` 零工程专属路径** —— 工程内头文件靠 `-Iinc`（有编译数据库时按工程根解析）+
   `-I../inc`（没编译过时按文件所在目录解析，src\ 和 inc\ 下的文件都指向工程根\inc）两条互补相对路径；
   复制到哪、叫什么名字都不用改，只有换机器才动 Keil 那两行。
4. **STARTUP.A51 已注册** —— 不注册会链出 `L127 UNRESOLVED EXTERNAL ?C_START`。
5. **文件已注册**（srcDirs: inc + src）—— 不注册会编译 0 个 C 文件（"C Files: 0"），同样链出 ?C_START 错误。
6. **工具链 Keil_C51** —— EIDE 新建有时默认 SDCC，会报"找不到编译器"。

## 加入你自己的代码

- 新 C 文件放 `src\`，新头文件放 `inc\`（和 uart 模块同目录的规则）。
- 新文件要在 EIDE 面板的工程树上右键 → 添加文件（或在资源管理器拖进 src/inc 文件夹，
  EIDE 自动识别 srcDirs 内的文件）。
- 注意：本机 C51 是**评估版**（RESTRICTED，代码上限 2KB）。代码超过 2048 字节会报
  CODE SIZE LIMIT EXCEEDED —— 需要激活正式版 license。
